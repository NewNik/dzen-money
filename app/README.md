# dzen-money: приложение

Письма Vietcombank из Gmail → операции в Дзен-мани. Работает в Google Apps Script по таймеру.

## Устройство
- `src/core` — чистый TypeScript: разбор писем, правила категорий, сборка операций, поиск дублей. Без API Node и Apps Script.
- `src/gas/main.ts` — Gmail, свойства скрипта, запросы к Дзен-мани, Telegram.
- `config/category-rules.json` — общие правила категорий (описание: `../kb/category-rules.md`).
- `fixtures/vcb` — обезличенные письма четырёх типов.

## Команды
| Команда | Что делает |
|---|---|
| `npm test` | тесты |
| `npm run typecheck` | проверка типов |
| `npm run build` | сборка `dist/Code.js` и `dist/appsscript.json` |
| `npm run push` | сборка и `clasp push` |

## Установка
1. `npm install`, затем `npm run build`.
2. Создать проект на https://script.google.com под тем аккаунтом Google, куда приходят письма банка.
3. Перенести код одним из способов:
   - вручную: содержимое `dist/Code.js` — в файл `Code.gs`; в настройках проекта включить показ `appsscript.json` и заменить его содержимым `dist/appsscript.json`;
   - через clasp: `npm i -g @google/clasp`, `clasp login`, скопировать `.clasp.json.example` в `.clasp.json`, вписать ID проекта, `npm run push`.
4. В «Настройки проекта → Свойства скрипта» задать свойства из таблицы ниже.
5. Запустить функцию `check` — она проверит токен и напечатает счета Дзен-мани с их id.
6. Запустить функцию `setup` — создаст ярлыки и таймер на каждые 10 минут.

## Свойства скрипта
| Свойство | Обязательно | Значение |
|---|---|---|
| `ZEN_TOKEN` | да | токен Дзен-мани |
| `ACCOUNTS` | да | `{"accounts":{"<номер счёта VCB>":"<id счёта в Дзен-мани>"}}` |
| `CATEGORY_RULES_LOCAL` | нет | личные правила: `[{"beneficiary":"…","tag":"Питание / Продукты"},{"beneficiary":"…","transferTo":"<название счёта>"}]` |
| `DRY_RUN` | нет | `true` (по умолчанию) — ничего не пишет; `false` — боевой режим |
| `LOOKBACK_DAYS` | нет | за сколько дней искать письма, по умолчанию 5 |
| `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID` | нет | куда слать отчёты; без них — только журнал выполнения |

Служебные свойства `PROCESSED`, `PROCESSED_DRY`, `FAILS` скрипт ведёт сам.

## Как работает запуск
1. Ищет письма от `VCBDigibank@info.vietcombank.com.vn` за последние дни, берёт сообщения, которых ещё не обрабатывал.
2. Отбрасывает письма без DKIM/SPF/DMARC = pass.
3. Разбирает письмо. Не разобралось — ярлык `zen/unparsed`.
4. Читает из Дзен-мани справочники и операции за последние дни (один запрос).
5. Для каждого письма:
   - операция с тем же id или маркером `[vcb:<номер>]` уже есть — пропуск (в том числе если её удалили вручную);
   - есть похожая, внесённая вручную (±2 дня, сумма с допуском 3 %) — пропуск; при неточном совпадении — строка в отчёте;
   - иначе строит операцию: категория по правилам, сомнительные помечаются `[проверить]` в комментарии.
6. В боевом режиме отправляет все новые операции одним запросом и проверяет, что они появились.
7. После пяти неудач письмо больше не берётся (ярлык `zen/error`).

Удаления в Дзен-мани не отправляются никогда.

## Пробный и боевой режим
Сначала `DRY_RUN=true`: отчёты показывают, что было бы создано, запись и ярлыки не ставятся. Обработанные в пробном режиме письма запоминаются отдельно, поэтому после `DRY_RUN=false` письма за последние `LOOKBACK_DAYS` дней будут загружены по-настоящему.
