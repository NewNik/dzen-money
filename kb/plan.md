# План: письма Vietcombank → Gmail → Дзен-мани

Дата: 2026-11-10. Основано на исследовании (GitHub zenmoney/ZenPlugins, wiki ZenMoney API, документация Google).

## Решение
Письма Vietcombank обрабатывает Google Apps Script по таймеру (5–10 мин), операции пишутся в Дзен-мани через `POST /v8/diff/`. Ядро (парсер, маппинг, клиент) — чистый TypeScript, тестируется локально, собирается в Apps Script. См. [decisions/0001](decisions/0001-apps-script-portable-core.md).

Почему:
- Публичный API Дзен-мани есть, но регистрация своего OAuth-приложения ограничена. Для личного использования wiki предлагает токен от зарегистрированного сервиса (Zerro.app).
- Apps Script: бесплатно, без сервера, без верификации OAuth-приложения Google и без продления Gmail watch (раз в 7 дней).
- Плагин ZenPlugins для чтения почты — тупик: песочница на устройстве, публикация через PR, для Вьетнама в основном разбор SMS/пушей (репозиторий zenmoney/sms-formats).

Главный неподтверждённый риск: срок жизни и стабильность токена Дзен-мани в 2026 году. Проверяется на этапе 0 до написания кода.

## Архитектура
1. Gmail-фильтр метит письма от `VCBDigibank@info.vietcombank.com.vn` меткой `zen/inbox`.
2. Apps Script раз в 5–10 мин берёт размеченные письма, проверяет DKIM/SPF/DMARC.
3. Парсер разбирает HTML по двуязычным подписям.
4. Маппер строит Transaction Дзен-мани, id = UUIDv5 от Order Number (повтор безопасен).
5. Один `/v8/diff/` на запуск. Метки Gmail — машина состояний: `zen/inbox` → `zen/done` | `zen/unparsed` | `zen/error`.

Сравнение вариантов получения писем и хостинга:

| Вариант | Итог |
|---|---|
| Apps Script + GmailApp | выбран |
| Gmail API + Pub/Sub | почти реальное время, но Cloud-проект, продление watch, 7-дневный refresh-токен в режиме Testing |
| IMAP + app password | слишком широкий доступ, Google не рекомендует |
| Node на VPS / Cloud Run | запасной вариант, ядро переносится без изменений |
| GitHub Actions по расписанию | расписание отключается после 60 дней без активности, данные в логах CI |
| n8n / Make | нет узла Дзен-мани |
| Свой Zen-плагин | не рекомендуется |

Квоты Apps Script (consumer-аккаунт): 6 мин на запуск, 90 мин триггеров в день, 20 000 URL Fetch в день, 20 триггеров на скрипт — с запасом.

## Этапы

| Этап | Цель | Критерий готовности | Оценка |
|---|---|---|---|
| 0. Разведка API | токен zerro.app/token; `POST /v8/diff/` с `serverTimestamp: 0` (при ошибке — `api.zenmoney.app`); найти id VND, UUID счёта VCB, user id; тестовый расход 1 VND; повтор с тем же UUID | операция появилась, повтор не создал дубль | 2–4 ч |
| 1. Парсер | `htmlToCells`, словарь подписей, нормализация даты и суммы, 3–5 фикстур, Vitest | все фикстуры дают верный результат; тесты на `00:15` и `1,234,567` | 4–6 ч |
| 2. Получение писем | Gmail-фильтр + метка, clasp-проект, проверка `Authentication-Results`, таймер | новое письмо попадает в лог за 10 мин | 3–4 ч |
| 3. Запись в Дзен-мани | клиент `zenDiff()` (401/429/5xx), полный Transaction, dry-run | операция в приложении с верными датой, суммой, счётом | 4–6 ч |
| 4. Маппинг и категории | конфиг счетов, `rules.json`, `/v8/suggest/`, комиссия отдельной операцией, переводы между своими | ≥80% операций за 2 недели с категорией | 4–6 ч |
| 5. Дедупликация | UUIDv5, метки как состояние, проверка похожей ручной операции ±1 день, маркер `[vcb:…]` | повторный прогон ничего не меняет | 3–4 ч |
| 6. Деплой и мониторинг | Telegram-алерты, ежедневная сводка, 1–2 недели dry-run, боевой режим | 14 дней без ручных вмешательств | 4–6 ч + 2 нед. |
| 7. Другие типы писем | по 3–5 образцов на тип, парсер на тип, интерфейс `BankParser`, LLM-fallback с подтверждением | ≥95% писем за месяц без LLM | 2–4 ч на тип |

Итого: MVP (этапы 0–5) 20–30 ч; этап 6 — 4–6 ч плюс 2 недели наблюдения; этап 7 — 10–25 ч.

Запасные варианты: токен не выдаётся → заявка на OAuth-клиент через форму из wiki, временно CSV-импорт. Сервер требует недокументированные поля → сверяться с ZenPlugins issue #1236 и копировать форму существующей транзакции. Нет писем по части операций → просить Дзен-мани добавить формат VCB в `sms-formats`.

## Парсинг писем
- Не привязываться к позициям ячеек. HTML → последовательность текстовых ячеек (trim, схлопнуть пробелы и `&nbsp;`), значение — первая непустая ячейка после подписи. NFC-нормализация, без учёта регистра.
- Регулярки вместо DOM/cheerio: в Apps Script нет DOM и npm, ядро остаётся переносимым.
- Подробности и словарь подписей: [vcb-emails/transfer-receipt.md](vcb-emails/transfer-receipt.md).
- Неизвестный формат → метка `zen/unparsed`, алерт, сохранить HTML как фикстуру.
- LLM (Claude) — только как подсказка для неизвестных писем с ручным подтверждением, не в контуре автозаписи; перед отправкой маскировать номера счетов; сумма из ответа должна буквально встречаться в тексте письма. Стоимость порядка $0,003–0,004 за письмо.

## Маппинг в Дзен-мани
- Счета: конфиг `{ "<номер счёта>": "<UUID счёта в Дзен-мани>" }`; у счёта в Дзен-мани `syncID: ["0851"]`.
- Валюта: id VND из `instrument[]`, кэшировать.
- Категории: правила `{ match, field, tag, merchant }` (подстрока/regex, без учёта регистра и диакритики) → затем `/v8/suggest/` → без категории. Раз в неделю добавлять правила для некатегоризированных.
- `payee` — нормализованное имя, `originalPayee` — как в письме, `comment` — Details of Payment + `[vcb:<order>]`.
- Комиссия > 0 — отдельная операция (id от `vcb:<order>:fee`).
- Переводы между своими счетами — одна операция; если обе стороны автоматизированы, id от Order Number отправителя.
- Дубли с ручным вводом: перед записью смотреть ±1 день по тому же счёту; при совпадении суммы без маркера `[vcb:…]` — не создавать, пометить в Telegram.

Пример расхода из образца письма: `outcomeAccount = incomeAccount = <UUID счёта VCB>`, `outcome = 74000`, `income = 0`, оба инструмента VND, `date = '2026-11-08'`.

## Безопасность
- Токен Дзен-мани только в Script Properties (или `.env` вне git). Даёт полный доступ на запись. Клиент никогда не отправляет `deletion`.
- Логи и Telegram без полных номеров счетов и имён (`****0851`).
- Фикстуры обезличивать до коммита.
- Gmail: в варианте Apps Script токены Google не покидают Google.

## Тестирование и мониторинг
- Фикстуры: 10–20 писем каждого типа в `app/fixtures/vcb/<тип>/*.html` + `*.expected.json`.
- Unit-тесты: парсинг, граничные случаи (сумма, время `00:15`, неизвестная валюта, отсутствие подписи → ошибка, а не 0), маппинг, детерминированность UUID.
- `DRY_RUN=true`: парсит, строит Transaction, пишет в лог/Telegram, но не записывает. 1–2 недели.
- Алерты: ошибка парсинга, 401 от Дзен-мани, исключение, письмо без DKIM. Ежедневная сводка; 0 писем 3 дня подряд — подозрение на сломанный фильтр.
- После 5 неудач письмо уходит в `zen/error`.

## Что не подтверждено
- Срок жизни токена zerro.app в 2026 году.
- Лимиты частоты запросов Дзен-мани (не опубликованы).
- Обязательные поля API меняются без документации (issue #1236 — наблюдения сообщества).
- Форматы других писем Vietcombank (банк их не документирует).
- Плагин Vietcombank в ZenPlugins не найден, но проверка по неполному листингу.
