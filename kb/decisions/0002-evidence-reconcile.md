# 0002. Чеки и заказы — «подтверждения», сверка в каждом запуске

Дата: 2026-11-11. Статус: принято, реализовано для чеков Grab; проверяется в dry-run.

## Решение
Чек Grab (позже — заказ Shopee) операцию не создаёт. Это «подтверждение»: оно уточняет категорию и комментарий операции, записанной по письму банка. Подтверждение ждёт свою операцию в почте под ярлыком `zen/receipt`, каждый запуск сверяет ожидающие подтверждения с операциями этого запуска и с уже записанными. Порядок прихода чека и письма банка не важен.

Код: `app/src/core/zen/evidence.ts` (`Evidence`, `reconcile`), подключение — `syncToZen` в `app/src/gas/main.ts`.

## Условие совпадения (Grab)
Расход с любого своего счёта VCB, та же сумма и валюта, тот же день (заказ после 23:00 — и следующий день), получатель — физлицо, на операции нет метки другого чека.

## Границы правок (согласовано 11.11.2026)
1. Правятся только операции скрипта (метка `[vcb:…]`).
2. Категория меняется, если она пустая, поставлена скриптом по эвристике «перевод физлицу» либо операцию после записи не трогал человек (`changed − created ≤ 60 с`: так выглядит автокатегория сервера). Иначе категория остаётся, дописывается только комментарий.
3. Ручные операции не правятся — только подсказка в Telegram.
4. В комментарий дописываются ресторан и метка `[grab:<номер заказа>]`; операция с меткой повторно не правится.
5. Несколько операций скрипта с той же суммой в тот же день — не угадывать, `zen/receipt-unmatched` и сообщение.
6. Удаления нет: уже записанная операция отправляется целиком с новым `changed`.

Пункт 2 шире исходной формулировки («пустая или эвристическая») на случай автокатегории сервера: операции вне диапазона эвристики уходят с `tag: null`, Дзен-мани сам ставит им категорию по получателю, и без этого условия чек их не исправил бы.

## Когда запрашивается Дзен-мани
Полная выгрузка ради чека — один раз для нового чека (операция могла быть записана раньше) и один раз по истечении срока. Между ними чек сверяется попутно, когда приходит письмо банка и выгрузка всё равно делается. Срок ожидания — 3 дня.

## Состояние
| Где | Что |
|---|---|
| Ярлык `zen/receipt` | чек ждёт операцию |
| `zen/receipt-done` | операция уточнена, метка уже стояла, совпала ручная операция, либо письмо не требует сверки (поездка, реклама) |
| `zen/receipt-dryrun` | совпадение найдено, режим dry-run; при включении записи вернуть `zen/receipt` |
| `zen/receipt-unmatched` | операция не появилась за 3 дня либо кандидатов несколько |
| Свойство `RECEIPT_IDS` | id чеков с окончательным итогом |
| Свойство `RECEIPT_CHECKED` | id чеков, уже сверенных с полной выгрузкой |

## Отвергнуто
- Только подсказка в Telegram: категорию всё равно ставит человек.
- Только «чек раньше письма»: порядок бывает любым.
- Задержка записи операции до прихода чека: операции появляются с опозданием, нужно хранить отложенные.
- Сверка раз в день: категория уточняется с задержкой до суток.

## Shopee
Тот же механизм: свой парсер письма и своя функция `…Evidence` (получатель, окно дат, категория по товару). По словам владельца, заказы Shopee тоже оплачиваются переводом курьеру и в Shopee почти всегда значатся как оплата наличными. Настройка и проверка — отдельным шагом.

## Не проверено
- Работа в Apps Script: проверена сборка и ядро (тесты, прогон `reconcile` на выгрузке Дзен-мани только на чтение), живого запуска не было.
- Проходят ли письма Grab проверку DKIM/DMARC для `grab.com` — покажет `dumpGrabSample`. Если нет, чеки уйдут в `zen/quarantine`.
- Меняет ли просмотр операции в приложении поле `changed` (тогда условие «не трогал человек» сработает реже, это безопасная сторона).
