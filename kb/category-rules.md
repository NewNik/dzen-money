# Правила сопоставления категорий расходов

Дата: 2026-11-10. Основано на снимке Дзен-мани (`POST /v8/diff/`, `serverTimestamp: 0`, только чтение).
Машиночитаемая версия: [app/config/category-rules.json](../app/config/category-rules.json).

## На чём основано

| Показатель | Значение |
|---|---|
| Операций всего (не удалённых) | 2 975 |
| Расходов | 2 495 |
| Расходов со счетов VCB (Ник + Юля) | 1 157, с 2025-11 по 2026-11, ~100 в месяц |
| Расходов с одной категорией | 99,2 % (12 с двумя, 8 без категории) |
| Расходов с текстом (получатель или комментарий) | 862 из 2 495 (35 %) |
| Расходов VND с именем получателя | единицы; три операции уже с маркером `[vcb:…]` |

Главное ограничение: **в истории почти нет имён получателей** — операции вносились вручную, чаще без текста.
Поэтому соответствие «получатель из письма VCB → категория» из истории вывести нельзя. Что из неё выведено:

1. как вы сами относите покупки к категориям (словарь из комментариев) — раздел «Границы категорий»;
2. профиль сумм по категориям — раздел «Подсказки по сумме»;
3. какие категории живые, а какие заброшены.

Ключевые слова по вьетнамским продавцам (EVN, WinMart, Pharmacity и т. п.) — **предположения из общих знаний**, в файле правил помечены `source: assumption` или `mixed`. Их нужно подтвердить первыми реальными письмами.

## Порядок применения

Срабатывает первое подходящее правило. Операции всегда назначается **одна** категория.

| Шаг | Что проверяется | Результат |
|---|---|---|
| 0 | Это не расход: оба счёта свои, снятие наличных, долг | перевод, без категории (см. ниже) |
| 1 | Личное правило по номеру счёта получателя (выученное) | категория, без проверки |
| 2 | Ключевые слова в имени получателя | категория из `rules[]` |
| 2а | Получатель — физлицо без личного правила, сумма 140–450 тыс., кратна 1 000 | «Питание / Доставка еды», на ручную проверку |
| 3 | Маркетплейс (Shopee, Lazada, TikTok Shop) без уточняющих слов | продавец заполнен, категории нет, на ручную проверку |
| 4 | `/v8/suggest/` Дзен-мани | категория, на ручную проверку |
| 5 | Подсказка по сумме | категория, на ручную проверку |
| 6 | Ничего не подошло | без категории, в еженедельный разбор |

Не подставлять «Продукты» по умолчанию: это самая частая категория, но всего 30 % расходов VCB.

### Шаг 0. Не расходы

| Признак | Как записывать |
|---|---|
| Счёт получателя — второй свой VCB (Ник ↔ Юля, 14 переводов за историю, обычно 1–3 млн, до 10 млн) | перевод между счетами, одна операция |
| Снятие наличных в банкомате | перевод на «VND \| Наличные» (7 раз, от 50 тыс. до 15 млн) |
| Входящий перевод после продажи USDT на Bybit (20 раз) или с BAKAI (7 раз) | не создавать автоматически: сумма списания в USDT/KGS из письма неизвестна. Помечать для ручного ввода |
| Депозит за аренду, займы знакомым | перевод на счёт «Долги», не расход |
| Входящий возврат от продавца | доход «Продажа вещей» (так размечен возврат за шорты), на ручную проверку |
| Комиссия банка (`Charge Amount > 0`) | отдельный расход, категория «Подписки» (так размечены «Обслуживание карты», «Обслуживание банка») |

Номера своих счетов и счетов получателей — только в локальном конфиге, не в git.

### Шаг 1. Личные правила (обучение)

Получатель в письмах VCB чаще всего — физлицо (QR-оплата у мелкого продавца, курьер). По имени категорию не определить, зато один и тот же счёт получателя почти всегда означает одну категорию.

- Ключ — нормализованное имя получателя + банк. Номер счёта не годится: по письмам он часто виртуальный и меняется от платежа к платежу (см. [vcb-emails/transfer-receipt.md](vcb-emails/transfer-receipt.md)).
- Раз в неделю читать операции с маркером `[vcb:…]`: если категорию поставили или исправили вручную, записать пару «получатель → категория».
- Правило включается после **двух** наблюдений, если одна категория набирает не меньше 60 %; иначе получатель помечается «на проверку».
- Перевод на имя второго владельца — перевод между своими счетами; имя задаётся в локальном конфиге.
- Хранить в Script Properties или `app/config/category-rules.local.json` (в `.gitignore`). В git имена и счета не попадают.

По выгрузке писем собрано: 13 активных правил, 1 получатель «на проверку», 59 кандидатов с одним наблюдением.

### Шаг 2. Ключевые слова

Текст для поиска: для писем VCB — только имя получателя; для ручных операций — получатель + комментарий.
Нормализация: нижний регистр, без диакритики, `đ→d`, `ё→е`, пробелы схлопнуть, маркер `[vcb:…]` вырезать.
Каждый шаблон — регулярное выражение, совпадение только с начала слова: `(?<![\p{L}\p{N}])(?:шаблон)`, флаги `iu`.

### Шаг 5. Подсказки по сумме

Применять, только если шаги 1–4 ничего не дали, и всегда с пометкой «на проверку». Статистика по расходам VCB:

| Сумма, VND | Категория | Совпадений в истории |
|---|---|---|
| от 5 000 000 | Жильё / Аренда | 7 из 8 (ещё один — визаран) |
| ровно 70 000 | Питание / Рестораны | 26 из 29 |
| ровно 56 000 | Питание / Рестораны | 14 из 16 |
| ровно 33 000 | Транспорт | 12 из 13 |
| ровно 34 000 | Транспорт | 11 из 14 |
| ровно 38 000 | Транспорт | 8 из 10 |
| ровно 27 000 | Питание / Продукты | 8 из 8 |

Это привычные чеки в одних и тех же местах. Как только заработают личные правила по счёту получателя, они заменят эти подсказки — тогда раздел удалить.

Что суммой **не** определяется:
- 200 000 — «Связь» лишь в 10 случаях из 17; надёжно только вместе с оператором в получателе.
- Некруглая сумма (не кратна 1 000) — признак онлайн-заказа или счёта за коммуналку, но категорий там полтора десятка.
- Диапазон 20–400 тыс. — «Продукты», «Рестораны», «Хотелки» перемешаны примерно поровну.

Справочно, типичные суммы (медиана, VND): Транспорт 33 тыс. (три четверти до 38 тыс.), Продукты 81 тыс., Рестораны 80 тыс., Хотелки 80 тыс., Доставка еды 295 тыс. (минимум 132 тыс.), Коммуналка 1,1 млн, Аренда 9,2–13 млн.

## Проверка на истории

Правила шага 2 прогнаны по расходам, где есть получатель или комментарий:

| Выборка | Операций | Покрытие | Точность | Точность до родительской категории |
|---|---|---|---|---|
| Все валюты | 859 | 95 % | 87 % | 97 % |
| Только VND | 367 | 98 % | 95 % | 97 % |

Как это читать:
- Это проверка **на тех же данных, по которым правила составлены**, а не на новых. Реальная точность будет ниже.
- Проверялись русские комментарии, а не тексты писем VCB. Сколько писем закроет словарь вьетнамских продавцов — неизвестно, пока нет образцов.
- Ошибки в VND — почти все из раздела «Спорные случаи» («вода», «паркинг», «батарейки»).
- Без шаблона остались личные пометки («тест», «игры с») и получатели-физлица.

Цель этапа 4 из плана (≥80 % операций с категорией за две недели) достижима в основном за счёт шага 1 — личных правил по счёту получателя.

| Результат | Писем | Доля |
|---|---|---|
| Операция с той же суммой, ±1 день, тот же счёт | 105 | 57 % |

- Получателей 93, из них 70 встретились один раз. Назначение платежа смысла не несёт, работает только имя получателя.
- **Физлица-одиночки** (40 расходов): в диапазоне 140–450 тыс. это доставка еды в 17 случаях из 20 — курьеры. Ниже 45 тыс. — чаще транспорт (4 из 8), но ненадёжно.
- **Сети магазинов не равны «Продуктам»**: WinMart — «Хотелки» в 9 случаях из 10, «Mini Mart» — 6 из 6, Bach Hoa Xanh — поровну «Продукты» и «Хотелки» (6 и 6). Категория зависит от того, что куплено, а не где.
- Bach Hoa Xanh приходит под пятью написаниями имени и через пять банков — сопоставлять по подстроке, не по точному имени.
- Один получатель (20 писем) — магазин или посредник с восемью разными категориями. Категорию не ставить.
- Платёжные шлюзы (Payoo, Baokim, MoMo, ShopeePay) стоят в имени перед настоящим продавцом или вместо него — сами по себе категорию не определяют.
- Перевод на имя второго владельца счёта — всегда перевод между своими счетами (7 из 7).

### Точность правил на письмах

Проверка на 128 сопоставленных расходах с категорией.

| Способ | Сработало | Верно |
|---|---|---|
| Ключевые слова, первая версия (до писем) | 20 | 12 |
| Ключевые слова, версия 2 | 29 | 25 |
| Личное правило по получателю (категория предсказана по другим операциям того же получателя) | 40 | 34 |
| Физлицо, 140–450 тыс., сумма кратна 1 000 → «Доставка еды» | 20 | 17 |
| **Всё вместе** | **75 (59 %)** | **61 (81 % от назначенных)** |

- Версия 2 ключевых слов и правило про курьеров подобраны по этим же письмам — на новых данных точность будет ниже. Честно проверено только личное правило (85 %).
- Без категории остаётся 41 % расходов: получатели, встреченные один раз, и магазины со смешанными покупками.
- Цель плана «≥80 % операций с категорией» одними правилами недостижима. Реалистично: около 60 % автоматически, остальное — подсказка с подтверждением.

## Сопровождение

- Первые две недели — dry-run: в лог писать id сработавшего правила и шаг, запись в Дзен-мани не делать.
- Раз в неделю: разбор операций без категории и с пометкой «на проверку»; новые слова — в `category-rules.json`, новые получатели — в локальные правила.
- Шаблон, давший две ошибки подряд, сужать или удалять.
- После появления 3–5 реальных писем каждого типа — пересмотреть группы с `source: assumption`.
- Категории ищутся по названию (с обрезкой пробелов: в Дзен-мани «Досуг », «Жильё », «Одежда » записаны с пробелом в конце), id берётся из ответа diff.

## Формат `category-rules.json`

| Поле | Смысл |
|---|---|
| `rules[].id` | имя правила для логов |
| `rules[].tag` | путь категории «Родитель / Подкатегория»; `null` — категорию не ставить |
| `rules[].match` | список регулярных выражений по нормализованному тексту |
| `rules[].amountMin`, `amountMax` | ограничение по сумме в VND (включительно снизу, строго сверху) |
| `rules[].merchant` | название продавца в Дзен-мани |
| `rules[].confidence` | `high` — записывать как есть; `medium` и `low` — помечать на проверку в первые недели |
| `rules[].source` | `history` — из ваших комментариев; `assumption` — из общих знаний; `mixed` |
| `rules[].needsReview` | всегда на ручную проверку |
| `neverAssign` | категории, запрещённые для автоназначения |
| `feeTag` | категория для комиссии банка |
| `amountHints` | подсказки по сумме (шаг 5) |
