# Установка в Google Apps Script

По умолчанию скрипт работает в режиме dry-run: читает письма, сверяет с Дзен-мани и пишет в журнал, но ничего не записывает. Запись включается свойством `MODE` (раздел 6).
Всё делается в **основном** аккаунте Google, кроме шага 2.

## 1. Фильтр в основном Gmail
Настройки → «Фильтры и заблокированные адреса» → «Создать фильтр»:
- От: `VCBDigibank@info.vietcombank.com.vn`
- Действие: «Применить ярлык» → новый ярлык `zen/inbox`.

## 2. Второй ящик: автопересылка
Во **втором** Gmail:
1. Настройки → «Пересылка и POP/IMAP» → «Добавить адрес пересылки» → основной адрес. На основной ящик придёт письмо с кодом — подтвердить.
2. Создать фильтр: От `VCBDigibank@info.vietcombank.com.vn` → «Переслать на» основной адрес.

Пересланное письмо сохраняет отправителя банка, поэтому в основном ящике на него сработает фильтр из шага 1. Скрипт и токен — одни на оба счёта.

## 3. Проект Apps Script
1. Открыть https://script.google.com → «Создать проект», назвать `dzen-money`.
2. В файл `Код.gs` вставить целиком содержимое `app/build/Code.js` (заменив всё, что там было).
3. «Настройки проекта» → включить «Показывать файл манифеста appsscript.json» → вставить в него содержимое `app/build/appsscript.json`.
4. Сохранить. На панели над кодом, в выпадающем списке функций (справа от кнопок «▷ Выполнить» и «Отладка»), выбрать `install` и нажать «▷ Выполнить». После выдачи доступа (шаг 5) внизу откроется «Журнал выполнения» со строкой «Метки созданы, таймер установлен (каждые 5 минут).»
   > Синюю кнопку «Начать развертывание» в правом верхнем углу **не нажимать**: она публикует скрипт как веб-приложение или API. Здесь это не нужно, таймер работает без развертывания.
5. Google попросит доступ к почте. Появится предупреждение «приложение не проверено» — это нормально для личного скрипта: «Дополнительные настройки» → «Перейти на страницу dzen-money».

`install` создаёт ярлыки `zen/*` и таймер на каждые 5 минут. Остановить — функция `uninstall`.

## 4. Проверка
- Дождаться нового письма банка (или вручную повесить ярлык `zen/inbox` на старое).
- Через 5–10 минут: слева «Выполнения» → запуск `run` → в журнале строка `[dry-run] parsed … 74000 VND …`.
- Письмо получает ярлык:

| Ярлык | Что значит |
|---|---|
| `zen/done` | записано в Дзен-мани (или уже было записано) |
| `zen/dryrun` | готово к записи, но режим dry-run |
| `zen/duplicate` | похоже на операцию, внесённую вручную (тот же счёт и сумма, дата ±1 день) — не записано, проверить |
| `zen/unparsed` | формат письма или счёт не распознан — причина в журнале |
| `zen/quarantine` | не прошла проверка отправителя или DKIM/DMARC |
| `zen/error` | исключение в скрипте, нет `ZEN_TOKEN` или 5 сбоев Дзен-мани подряд |

Запустить разбор сразу, не дожидаясь таймера: выбрать в списке функций `run` → «▷ Выполнить».

### Повторный разбор письма
Скрипт запоминает (свойство `PROCESSED_IDS`) только письма с окончательным итогом: `zen/done`, `zen/duplicate`, `zen/quarantine`. Остальные (`zen/dryrun`, `zen/unparsed`, `zen/error`) разбираются заново, если снять ярлык и повесить `zen/inbox`.
Запомненное письмо пропускается, в журнале `skip msg=… уже обработано`. Чтобы разобрать его заново, удалить id из `PROCESSED_IDS`. Дубля не будет: операция с тем же id в Дзен-мани не создаётся повторно.

## 5. Образец для фикстуры
Выполнить функцию `dumpSample` — в «Черновиках» появится письмо `zen sample: …` с обезличенным HTML последнего письма банка (цифры → `0`, значения полей → `x`, ссылки убраны). Просмотреть, что не осталось имён и номеров, и передать текст для фикстуры.

## 6. Запись в Дзен-мани (этап 3)
Свойства скрипта («Настройки проекта» → «Свойства скрипта»):

| Свойство | Значение |
|---|---|
| `ACCOUNTS` | `{"<номер счёта VCB>":"<UUID счёта в Дзен-мани>", …}` — номера только цифрами; в git не класть |
| `ZEN_TOKEN` | токен Дзен-мани (zerro.app/token). Даёт полный доступ к учёту — только сюда, не в чат и не в git |
| `MODE` | не задано — dry-run; `write` — запись включена |

1. После обновления кода выполнить вручную `checkZen`. Google попросит новое разрешение — «Подключение к внешнему сервису» (запросы к api.zenmoney.ru). В журнале: «Токен работает», по каждому счёту из `ACCOUNTS` — «счёт найден», режим.
2. Неделю-две в dry-run: в журнале `run` для каждого письма строка `create id=… -245000 acc=… comment="…"` — что будет записано; или `exists` / `manual-duplicate`.
3. Включить запись: `MODE` = `write`. Письма с `zen/dryrun`, которые нужно записать, вернуть в `zen/inbox`.
4. Выключить запись — удалить `MODE` или поставить любое другое значение.

Проверки перед записью (на каждый запуск, где есть разобранные письма, скрипт читает операции из Дзен-мани целиком, ~2,5 МБ):
- операция с тем же id (UUIDv5 от Order Number) уже есть → `exists`, не отправляется, правки в приложении не затираются;
- она удалена в приложении → `deleted`, не воскрешается;
- есть операция без маркера `[vcb:…]` на том же счёте с той же суммой, дата ±1 день → `manual-duplicate`, ярлык `zen/duplicate`;
- иначе → `create`. После записи сервер должен вернуть операцию в ответе, иначе `zen/error`.

Сбой Дзен-мани (сеть, 5xx, 401) — письмо остаётся в `zen/inbox` и повторяется в следующем запуске; после 5 сбоев подряд — `zen/error`. Счётчик в свойстве `RETRIES`.

## 7. Категории (этап 4)
Категорию ставят правила: первое совпавшее по получателю или назначению платежа. Без совпадения категория не передаётся — тогда её может угадать сам Дзен-мани (так 245 000 стало «Рестораны»).

- Встроенные правила — `app/config/rules.json` (компании: EVN, водоканалы). Попадают в `Code.js` при сборке.
- Личные — свойство скрипта `RULES`, проверяются раньше встроенных. Сюда — люди и места, которых не должно быть в git:

```json
[
  {"match": "nguyen van a", "field": "payee", "tag": "Рестораны"},
  {"match": "tien nha", "field": "details", "tag": "Аренда", "payee": "Аренда квартиры"}
]
```

| Поле | Что значит |
|---|---|
| `match` | подстрока или `/регулярка/`; регистр и вьетнамские диакритики не важны (`Nguyễn` = `nguyen`) |
| `field` | `payee` — получатель (у дохода — отправитель), `details` — назначение платежа, по умолчанию оба |
| `tag` | название категории как в приложении (подкатегория — своим названием, например `Коммуналка`) |
| `payee` | необязательно: каким получателем записать операцию |

Ошибки (нет категории, неверная регулярка, неверный JSON) — в журнале запуска; `checkZen` тоже проверяет правила.
Правила действуют только на новые операции: уже записанные скрипт не меняет, категорию у них править в приложении.

## Обновление кода
Вставить новый `app/build/Code.js` поверх старого. Вариант для тех, у кого локально есть Node: `npx @google/clasp login`, положить `app/.clasp.json` с `scriptId` и `"rootDir": "build"`, затем `npm run push`.
